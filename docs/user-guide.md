# Посібник користувача

Інформаційна система ветеринарної клініки, версія API 1.0.0.

Посібник описує щоденну роботу двох ролей системи: **адміністратора** і **лікаря**. Терміни відповідають глосарію [SRS §3](../spec/srs.md) і контракту API [openapi.yaml](../spec/api/openapi.yaml). Відповідність термінів і назв в інтерфейсі зведено в [розділі 6](#6-глосарій).

Як розгорнути й запустити систему, описано в [README](../README.md). Повний перелік операцій із технічними деталями є в [API-довіднику](api/index.md).

## 1. Початок роботи

### 1.1 Інтерфейс

Система надає REST API. Для роботи в браузері використовується **Swagger UI** за адресою `http://localhost:8081` (адресу на вашому сервері уточніть в адміністратора системи). Операції в ньому згруповано в розділи:

| Розділ Swagger UI | Що в ньому |
|---|---|
| Auth | вхід у систему |
| Users | облікові записи, довідник лікарів |
| Owners | власники |
| Patients | пацієнти та архівація карток |
| Schedule | сітка розкладу лікаря |
| Appointments | записи на прийом |
| Visits | прийоми та медична картка |
| Medications | каталог медикаментів і залишки |
| Notifications | сповіщення про низький залишок |

Щоб виконати операцію:

1. Розгорніть її, клацнувши на рядок операції (наприклад, `POST /auth/login`).
2. Натисніть **Try it out**. Поля стануть доступними для введення.
3. Заповніть параметри в таблиці **Parameters**: кожен параметр має окреме поле з його назвою (`q`, `ownerId`, `from` тощо). У посібнику параметри записано у вигляді адреси: `GET /owners?q=Коваленко` означає «у полі `q` введіть `Коваленко`», а `{patientId}` у шляху — поле `patientId`. Параметри з відповіддю «так/ні» (`active`, `read`, `lowStock`) обираються зі списку `true` / `false`.
4. Якщо операція має тіло запиту, поле **Request body** вже заповнене прикладом. Відредагуйте приклад: замініть значення своїми, зайві необов'язкові поля видаліть. Кнопка **Reset** повертає приклад.
5. Натисніть **Execute**.

Результат з'явиться нижче, у блоці **Responses**. Там показано **Curl** (той самий запит як команду), **Request URL** і **Server response**: код у колонці **Code** та тіло відповіді в **Response body**.

Введені значення зберігаються, доки сторінку не перезавантажено. Перед повторним пошуком очистіть фільтри, які вам більше не потрібні. Наприклад, залишений у полі `status` пошуку пацієнтів фільтр `ARCHIVED` сховає всі активні картки. Кнопка **Cancel** виходить із режиму введення.

Ту саму роботу можна виконувати будь-яким HTTP-клієнтом (Postman, `curl`), звертаючись до `http://<сервер>:8080/api/v1`.

### 1.2 Вхід у систему

Обліковий запис створює адміністратор (див. [3.1](#31-облікові-записи-персоналу)). Під час першого запуску системи автоматично створюється адміністратор `admin@clinic.example`; пароль для нього задає той, хто розгортає систему.

1. Розділ **Auth**, операція `POST /auth/login`.
2. Тіло запиту:

   ```json
   {
     "email": "admin@clinic.example",
     "password": "ваш-пароль"
   }
   ```

3. У відповіді `200` скопіюйте значення `accessToken`:

   ```json
   {
     "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
     "tokenType": "Bearer",
     "expiresIn": 28800,
     "user": {
       "id": "7d47c030-7c09-40f7-93ef-c7a11eef24c5",
       "email": "admin@clinic.example",
       "fullName": "Початковий адміністратор",
       "role": "ADMIN"
     }
   }
   ```

4. Натисніть кнопку **Authorize** із замком. Вона розташована після опису API, праворуч над списком розділів, поруч зі списком **Servers**.
5. У вікні **Available authorizations** вставте токен у поле **Value** без слова `Bearer`: Swagger UI додасть його сам. Натисніть **Authorize**. Вікно покаже **Authorized**; натисніть **Close**.

Тепер усі запити виконуються від вашого імені: замок на кнопці **Authorize** закритий, а в блоці **Curl** кожної відповіді видно заголовок `Authorization: Bearer …`.

Що важливо знати:

- Токен діє **8 годин** (`expiresIn: 28800` секунд), тобто приблизно робочу зміну. Після цього запити повертають `401`. Тоді просто увійдіть знову.
- Swagger UI не пам'ятає токен після перезавантаження сторінки. Після оновлення або повторного відкриття вкладки знову натисніть **Authorize** і вставте токен (або увійдіть заново).
- Щоб працювати під іншим обліковим записом (наприклад, адміністратор передає комп'ютер лікарю), увійдіть як інший користувач, відкрийте **Authorize**, натисніть **Logout**, вставте новий токен і натисніть **Authorize**.
- Операції виходу в системі немає. **Logout** і закриття вкладки лише прибирають токен зі сторінки, але сам токен лишається дійсним до завершення 8 годин. На спільному комп'ютері закривайте вкладку й не зберігайте токен у нотатках.
- Email не чутливий до регістру: `Admin@Clinic.example` і `admin@clinic.example` — той самий обліковий запис.
- Якщо обліковий запис деактивовано, вхід повертає `403 ACCOUNT_DEACTIVATED`, а вже виданий токен перестає діяти одразу.

### 1.3 Загальні правила

- **Ідентифікатори.** Кожен об'єкт має `id` у форматі UUID (наприклад, `cc5a216a-8851-48c0-b994-bc12f3667917`). Його повертає операція створення або пошуку; далі він підставляється в шлях або тіло інших запитів.
- **Час.** Час указується з часовим поясом, наприклад `2026-12-01T10:00:00+02:00`. Відповіді завжди повертаються за київським часом. Дати без часу мають формат `2026-12-01`.
- **Списки.** Довгі переліки віддаються сторінками: параметри `page` (з 1) і `pageSize` (до 100, за замовчуванням 20). Відповідь містить `items` і загальну кількість `total`.
- **Редагування.** У запиті на редагування передаються лише поля, які треба змінити. Значення `null` очищає необов'язкове поле.
- **Видалення немає.** Власників, пацієнтів, записи, прийоми й медикаменти не можна видалити: запит `DELETE` повертає `405`. Замість видалення змінюється статус: обліковий запис деактивується, картка пацієнта архівується, запис на прийом скасовується.

## 2. Що доступно кожній ролі

| Функціональна область | Адміністратор | Лікар |
|---|---|---|
| Облікові записи | створення, перегляд, деактивація | немає доступу |
| Довідник лікарів | перегляд | перегляд |
| Власники й пацієнти | реєстрація, пошук, редагування, архівація | лише перегляд і пошук |
| Розклад і записи на прийом | перегляд, створення, перенесення, скасування | лише перегляд |
| Медична картка (прийоми) | немає доступу | перегляд будь-якого пацієнта, збереження й редагування власних прийомів |
| Каталог медикаментів | додавання, редагування, коригування залишку | перегляд (вибір під час прийому) |
| Сповіщення про низький залишок | перегляд, позначення прочитаним | немає доступу |

Спроба виконати недоступну операцію повертає `403 FORBIDDEN` («Недостатньо прав»).

## 3. Сценарії адміністратора

### 3.1 Облікові записи персоналу

**Створити обліковий запис.** Розділ **Users**, `POST /users`:

```json
{
  "email": "ivanenko@clinic.example",
  "fullName": "Іваненко Олег Петрович",
  "role": "VETERINARIAN",
  "password": "початковий-пароль"
}
```

- `role`: `VETERINARIAN` для лікаря або `ADMIN` для адміністратора. Будь-який адміністратор може створювати облікові записи обох ролей.
- Пароль: від 8 до 72 символів. Передайте його працівнику безпечним способом. Змінити пароль через систему не можна.
- Email має бути унікальним без урахування регістру, інакше `409 EMAIL_TAKEN`.

Відповідь `201` містить `id` нового користувача і `"active": true`.

**Переглянути облікові записи.** `GET /users`. Фільтри: `role` (`ADMIN` або `VETERINARIAN`) і `active` (`true` або `false`).

**Деактивувати обліковий запис.** `POST /users/{userId}/deactivate`. Дія **необоротна**:

- користувач більше не може увійти, а його вже видані токени перестають діяти одразу;
- лікар зникає з довідника лікарів (`GET /doctors`), і на нього не можна створити новий запис;
- уже створені записи на прийом цього лікаря лишаються. Їх можна лише скасувати, перенести не можна (`422 DOCTOR_NOT_AVAILABLE`);
- останнього активного адміністратора деактивувати не можна (`409 LAST_ADMIN`).

### 3.2 Власники

**Зареєструвати власника.** Розділ **Owners**, `POST /owners`:

```json
{
  "fullName": "Коваленко Марія Іванівна",
  "phone": "+380671234567",
  "email": "kovalenko@example.com",
  "address": "м. Київ, вул. Садова, 12"
}
```

Обов'язкові поля: `fullName` і `phone`. Телефон пишеться цифрами без пробілів, дужок і дефісів (10–15 цифр, на початку можна `+`).

**Знайти власника.** `GET /owners?q=Коваленко`. Пошук іде за частиною ПІБ (від 2 символів) без урахування регістру; результати впорядковано за ПІБ.

**Редагувати власника.** `PATCH /owners/{ownerId}`. Передайте лише змінені поля, наприклад `{"phone": "+380501112233"}`.

### 3.3 Пацієнти

**Зареєструвати пацієнта.** Розділ **Patients**, `POST /patients`. Пацієнт завжди прив'язаний рівно до одного власника, тому спершу знайдіть або зареєструйте власника і візьміть його `id`:

```json
{
  "ownerId": "30f19578-b2a0-4c21-b7db-3c82e44c139b",
  "name": "Барсик",
  "species": "Кіт",
  "breed": "Британський короткошерстий",
  "sex": "MALE",
  "birthDate": "2021-03-15"
}
```

- Обов'язкові поля: `ownerId`, `name` (кличка), `species` (вид).
- `sex`: `MALE`, `FEMALE` або `UNKNOWN`. `birthDate` не може бути в майбутньому.
- Новий пацієнт отримує статус `ACTIVE`.

**Знайти пацієнта.** `GET /patients`. Параметри: `q` (частина клички), `ownerId` (усі тварини власника), `status` (`ACTIVE` або `ARCHIVED`).

**Редагувати базові дані.** `PATCH /patients/{patientId}`: кличка, вид, порода, стать, дата народження. Власника змінити не можна: поле `ownerId` дає `422 IMMUTABLE_FIELD`.

**Архівувати картку.** `POST /patients/{patientId}/archive` переводить картку в статус «Архівна» (`ARCHIVED`), наприклад після смерті тварини або припинення обслуговування. Дія **необоротна**:

- картка й історія прийомів зберігаються, лікарі можуть їх переглядати;
- нові записи на прийом для пацієнта створити не можна (`409 PATIENT_ARCHIVED`), прийоми не можна редагувати;
- поки в пацієнта є записи зі статусом «Заплановано», архівація відхиляється (`409 PATIENT_HAS_SCHEDULED_APPOINTMENTS`). Спершу скасуйте їх (див. [3.5](#35-записи-на-прийом)).

### 3.4 Розклад лікаря

Розклад складається зі **слотів** по 30 хвилин у **робочі години 09:00–18:00** **робочих днів (понеділок–п'ятниця)** за київським часом. Перший слот дня починається о 09:00, останній о 17:30. Субота й неділя — вихідні дні клініки.

1. Візьміть `id` лікаря з довідника: розділ **Users**, `GET /doctors`.
2. Розділ **Schedule**, `GET /doctors/{doctorId}/schedule?from=2026-12-01&to=2026-12-05`. Діапазон дат включає обидві межі й не може перевищувати 7 днів.

Відповідь містить список слотів:

```json
{
  "doctorId": "cafcbf0c-938f-41f1-b845-4531b7ef04ab",
  "from": "2026-12-01",
  "to": "2026-12-01",
  "slotMinutes": 30,
  "slots": [
    {
      "startsAt": "2026-12-01T09:00:00+02:00",
      "endsAt": "2026-12-01T09:30:00+02:00",
      "status": "FREE",
      "appointment": null
    }
  ]
}
```

- `FREE`: слот вільний, на нього можна записати пацієнта.
- `BOOKED`: слот зайнятий; у полі `appointment` є запис, пацієнт і його кличка. Слот зайнятий записом зі статусом «Заплановано» або «Завершено». Скасований запис слот звільняє.
- У вихідні вільних слотів немає. Якщо запис на вихідний був створений раніше, він показується як зайнятий слот.

### 3.5 Записи на прийом

**Створити запис.** Розділ **Appointments**, `POST /appointments`. Оберіть лікаря, пацієнта та вільний слот:

```json
{
  "doctorId": "cafcbf0c-938f-41f1-b845-4531b7ef04ab",
  "patientId": "cc5a216a-8851-48c0-b994-bc12f3667917",
  "startsAt": "2026-12-01T10:00:00+02:00"
}
```

Запис створюється зі статусом «Заплановано» (`SCHEDULED`); кінець слота `endsAt` система обчислює сама. Запис відхиляється, якщо:

| Ситуація | Відповідь |
|---|---|
| слот уже зайнятий іншим записом цього лікаря (конфлікт розкладу) | `409 SLOT_TAKEN` «Слот вже зайнятий» |
| день є суботою чи неділею | `422`, причина `NON_WORKING_DAY` «День є вихідним днем клініки» |
| час поза 09:00–18:00 (наприклад, 18:00) | `422`, причина `OUTSIDE_WORKING_HOURS` «Слот поза робочими годинами» |
| час не збігається з початком слота (наприклад, 10:15) | `422`, причина `SLOT_NOT_ALIGNED` «Початок не збігається з межею слота» |
| картку пацієнта архівовано | `409 PATIENT_ARCHIVED` |
| лікаря деактивовано або не знайдено | `422`, причина `DOCTOR_NOT_AVAILABLE` або `REFERENCE_NOT_FOUND` |

Різні лікарі можуть мати записи на той самий час. Конфлікт виникає лише для одного й того самого лікаря.

**Переглянути записи.** `GET /appointments` з фільтрами `doctorId`, `patientId`, `status` (`SCHEDULED`, `COMPLETED`, `CANCELLED`), `from`, `to`. Записи впорядковано за часом початку.

**Перенести запис.** `PATCH /appointments/{appointmentId}` з новим часом:

```json
{
  "startsAt": "2026-12-01T11:00:00+02:00"
}
```

Змінюється лише час у межах того самого лікаря; старий слот одразу звільняється. Перенести можна тільки запис зі статусом «Заплановано». Для нового часу діють ті самі перевірки, що й під час створення; якщо перевірка не пройшла, запис лишається на старому слоті.

**Скасувати запис.** `POST /appointments/{appointmentId}/cancel`. Статус стає «Скасовано» (`CANCELLED`), слот одразу звільняється. Запис не видаляється й лишається в історії. Скасувати можна тільки запис зі статусом «Заплановано», інакше `409 APPOINTMENT_NOT_SCHEDULED`. Скасування необоротне: щоб відновити прийом, створіть новий запис.

### 3.6 Каталог медикаментів і залишки

**Додати медикамент.** Розділ **Medications**, `POST /medications`:

```json
{
  "name": "Амоксицилін",
  "quantity": 10,
  "minThreshold": 5
}
```

- `quantity`: початковий залишок, ціле число від 0. Одиниця виміру в системі не ведеться: домовтеся в клініці, що означає «1» (таблетка, ампула, мл тощо), і за потреби вкажіть її в назві.
- `minThreshold`: мінімальний пороговий залишок, необов'язковий. Без порогу сповіщення для препарату не створюються.
- Назва має бути унікальною без урахування регістру, інакше `409 MEDICATION_NAME_TAKEN`.

**Редагувати медикамент.** `PATCH /medications/{medicationId}`: змінюються лише назва та поріг. Залишок так не змінюється.

**Скоригувати залишок вручну** (надходження, списання псування, виправлення помилки). `POST /medications/{medicationId}/adjust-stock` задає **зміну**, а не нове значення:

```json
{
  "delta": 20
}
```

Додатне `delta` збільшує залишок, від'ємне зменшує. Нуль не допускається. Залишок не може стати від'ємним: `409 NEGATIVE_STOCK` «Залишок не може бути від'ємним».

**Переглянути каталог.** `GET /medications`, пошук за частиною назви: `q`. Поле `lowStock: true` означає, що залишок нижчий за поріг; `GET /medications?lowStock=true` показує лише такі препарати.

### 3.7 Сповіщення про низький залишок

Коли лікар зберігає прийом і залишок препарату після списання стає **нижчим** за мінімальний поріг, система створює сповіщення для адміністраторів. Наприклад, при залишку 10 і порозі 5 списання 6 одиниць залишає 4, і з'являється сповіщення.

1. Розділ **Notifications**, `GET /notifications?read=false` показує непрочитані сповіщення:

   ```json
   {
     "id": "17f5249d-5614-4515-b125-85dd242f3305",
     "type": "LOW_STOCK",
     "medicationId": "4ce1a857-c87d-4312-8b09-247e4b9a71e3",
     "medicationName": "Амоксицилін",
     "quantity": 4,
     "minThreshold": 5,
     "read": false,
     "createdAt": "2026-11-24T15:19:14.274673+02:00"
   }
   ```

2. Поповніть залишок (див. [3.6](#36-каталог-медикаментів-і-залишки)).
3. Позначте сповіщення прочитаним: `POST /notifications/{notificationId}/mark-read`.

Що важливо знати:

- Поки для препарату є непрочитане сповіщення, нові для нього не створюються.
- Ручне коригування залишку сповіщень не створює. Поточний стан завжди видно в полі `lowStock` медикамента.
- Сповіщення показуються лише в системі; email чи інших каналів немає.

## 4. Сценарії лікаря

### 4.1 Свій розклад

- **Сітка слотів:** розділ **Schedule**, `GET /doctors/{doctorId}/schedule?from=…&to=…` з вашим `id` (його повертає вхід у полі `user.id`). Опис сітки є в [3.4](#34-розклад-лікаря).
- **Ваші записи:** розділ **Appointments**, `GET /appointments?doctorId=<ваш id>&status=SCHEDULED`.

Лікар лише переглядає розклад. Створення, перенесення й скасування записів виконує адміністратор (`403 FORBIDDEN`).

### 4.2 Медична картка пацієнта

Медична картка — це хронологія всіх прийомів пацієнта з діагнозами, призначеннями та витраченими медикаментами.

1. Знайдіть пацієнта: розділ **Patients**, `GET /patients?q=Барсик`, або візьміть `patientId` із запису на прийом.
2. Розділ **Visits**, `GET /patients/{patientId}/visits`. Прийоми впорядковано від найновішого до найстарішого.

Картку будь-якого пацієнта клініки може переглянути будь-який лікар, зокрема архівну. Адміністратор медичних карток не бачить.

### 4.3 Проведення прийому

Прийом зберігається за записом на прийом.

1. Знайдіть свій запис (див. [4.1](#41-свій-розклад)) і візьміть його `id`.
2. За потреби знайдіть `id` медикаментів у каталозі: розділ **Medications**, `GET /medications?q=Амокс`.
3. Розділ **Visits**, `POST /appointments/{appointmentId}/visit`:

   ```json
   {
     "diagnosis": "Гострий зовнішній отит",
     "prescriptions": "Амоксицилін 2 рази на день, 7 днів",
     "notes": "Повторний огляд через тиждень",
     "medications": [
       { "medicationId": "4ce1a857-c87d-4312-8b09-247e4b9a71e3", "quantity": 6 }
     ]
   }
   ```

   Обов'язковий лише діагноз. `medications` — витрачені під час прийому препарати; кожен препарат указується один раз, кількість від 1.

Після збереження (`201`) система **одночасно**:

- зберігає прийом із датою, що дорівнює початку запису;
- переводить запис у статус «Завершено» (`COMPLETED`);
- зменшує залишки вказаних медикаментів;
- створює сповіщення для адміністратора, якщо залишок став нижчим за поріг.

**Нестача медикаменту.** Якщо будь-якого препарату недостатньо, прийом **не зберігається взагалі**: не змінюються ні запис, ні залишки. Відповідь `409 INSUFFICIENT_STOCK` перелічує кожен препарат, якого бракує:

```json
{
  "code": "INSUFFICIENT_STOCK",
  "message": "Недостатній залишок: Новокаїн (доступно: 5, запитано: 8)",
  "details": [
    {
      "field": "medications[1].quantity",
      "reason": "INSUFFICIENT_STOCK",
      "message": "Недостатній залишок: Новокаїн (доступно: 5, запитано: 8)",
      "params": { "name": "Новокаїн", "available": 5, "requested": 8 }
    }
  ]
}
```

`medications[1]` — це другий препарат у вашому списку (нумерація з 0). Зменшіть кількість або приберіть препарат і збережіть прийом ще раз, або попросіть адміністратора поповнити залишок.

Прийом не зберігається також, якщо:

| Ситуація | Відповідь |
|---|---|
| запис призначено іншому лікарю | `403 NOT_ASSIGNED_DOCTOR` «Запис призначено іншому лікарю» |
| запис уже завершено або скасовано (зокрема прийом за ним уже збережено) | `409 APPOINTMENT_NOT_SCHEDULED` |
| картку пацієнта архівовано | `409 PATIENT_ARCHIVED` |
| препарат не знайдено в каталозі або вказано двічі | `422`, причина `REFERENCE_NOT_FOUND` або `DUPLICATE_MEDICATION` |

### 4.4 Виправлення прийому

`PATCH /visits/{visitId}`, наприклад:

```json
{
  "notes": "Повторний огляд 08.12.2026"
}
```

- Змінюються лише діагноз, призначення й нотатки.
- Перелік витрачених медикаментів після збереження змінити не можна (`422 IMMUTABLE_FIELD`): залишки вже списано. Помилку в кількості виправляє адміністратор ручним коригуванням залишку.
- Редагувати може лише автор прийому (`403 NOT_VISIT_AUTHOR`) і лише поки картка не архівна (`409 PATIENT_ARCHIVED`).

## 5. Повідомлення про помилки

Кожна помилка має однакову форму: код `code`, повідомлення українською `message`, HTTP-статус `status`, а для помилок полів — масив `details`, де `field` вказує поле запиту, а `reason` — причину.

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Дані запиту некоректні",
  "status": 422,
  "timestamp": "2026-11-24T15:19:13.71+02:00",
  "path": "/api/v1/appointments",
  "traceId": "d9349f39-b248-4245-96be-1487113da953",
  "details": [
    { "field": "startsAt", "reason": "NON_WORKING_DAY", "message": "День є вихідним днем клініки" }
  ]
}
```

Звертаючись до адміністратора системи щодо помилки, передайте значення `traceId`: за ним помилку знаходять у журналі.

### 5.1 Коди помилок

| Код | Статус | Повідомлення | Що робити |
|---|---|---|---|
| `UNAUTHORIZED` | 401 | Потрібна автентифікація | токен відсутній, протермінований або обліковий запис деактивовано: увійдіть знову через **Authorize** |
| `INVALID_CREDENTIALS` | 401 | Невірний email або пароль | перевірте email і пароль |
| `ACCOUNT_DEACTIVATED` | 403 | Обліковий запис деактивовано | зверніться до адміністратора клініки |
| `FORBIDDEN` | 403 | Недостатньо прав | операція недоступна вашій ролі (див. [розділ 2](#2-що-доступно-кожній-ролі)) |
| `NOT_ASSIGNED_DOCTOR` | 403 | Запис призначено іншому лікарю | прийом зберігає лікар, якому призначено запис |
| `NOT_VISIT_AUTHOR` | 403 | Прийом створено іншим лікарем | прийом редагує лише його автор |
| `NOT_FOUND` | 404 | Ресурс не знайдено | об'єкта з таким `id` немає; перевірте ідентифікатор |
| `METHOD_NOT_ALLOWED` | 405 | Метод не підтримується | видалення в системі немає: деактивуйте, архівуйте або скасуйте |
| `EMAIL_TAKEN` | 409 | Email вже зайнятий | оберіть інший email |
| `LAST_ADMIN` | 409 | Не можна деактивувати останнього адміністратора | спершу створіть іншого адміністратора |
| `USER_ALREADY_DEACTIVATED` | 409 | Користувача вже деактивовано | обліковий запис уже деактивовано |
| `SLOT_TAKEN` | 409 | Слот вже зайнятий | оберіть вільний слот у сітці розкладу |
| `APPOINTMENT_NOT_SCHEDULED` | 409 | Запис не у статусі «Заплановано» | завершений чи скасований запис змінити не можна |
| `PATIENT_ARCHIVED` | 409 | Картку пацієнта архівовано | для архівної картки доступний лише перегляд |
| `PATIENT_HAS_SCHEDULED_APPOINTMENTS` | 409 | У пацієнта є заплановані записи | скасуйте записи, потім архівуйте картку |
| `INSUFFICIENT_STOCK` | 409 | Недостатній залишок: … | див. [4.3](#43-проведення-прийому) |
| `NEGATIVE_STOCK` | 409 | Залишок не може бути від'ємним | зменште значення `delta` |
| `MEDICATION_NAME_TAKEN` | 409 | Медикамент з такою назвою вже існує | використайте наявний медикамент або іншу назву |
| `VALIDATION_ERROR` | 422 | Дані запиту некоректні | причину вказано в `details` (таблиця нижче) |
| `MALFORMED_REQUEST` | 400 | Запит не вдалося розібрати | запит не розібрано: перевірте JSON, формат UUID чи дати |
| `INTERNAL_ERROR` | 500 | Внутрішня помилка сервера | повідомте адміністратора системи значення `traceId` |

### 5.2 Причини в `details`

| Причина | Що означає |
|---|---|
| `REQUIRED` | обов'язкове поле не заповнено |
| `INVALID_FORMAT` | неправильний формат (email, телефон, дата, UUID) |
| `TOO_SHORT`, `TOO_LONG` | текст коротший або довший за допустимий |
| `OUT_OF_RANGE` | число чи дата поза допустимими межами |
| `INVALID_ENUM` | значення не з переліку (наприклад, роль чи стать) |
| `UNKNOWN_FIELD` | у запиті є поле, якого немає в операції |
| `IMMUTABLE_FIELD` | поле не можна змінити після створення |
| `EMPTY_BODY` | запит на редагування не містить жодного поля |
| `REFERENCE_NOT_FOUND` | вказаний власник, пацієнт, лікар чи медикамент не існує |
| `DOCTOR_NOT_AVAILABLE` | лікаря деактивовано |
| `SLOT_NOT_ALIGNED` | час не збігається з початком 30-хвилинного слота |
| `NON_WORKING_DAY` | день є вихідним днем клініки (субота, неділя) |
| `OUTSIDE_WORKING_HOURS` | слот поза робочими годинами 09:00–18:00 |
| `INVALID_RANGE` | дата `from` пізніша за `to` |
| `RANGE_TOO_LARGE` | діапазон розкладу довший за 7 днів |
| `DUPLICATE_MEDICATION` | препарат указано в прийомі двічі |
| `ZERO_DELTA` | зміна залишку дорівнює нулю |

## 6. Глосарій

| Термін (SRS §3) | У системі | Значення |
|---|---|---|
| Власник | `owner`, розділ **Owners** | фізична особа, відповідальна за тварину |
| Пацієнт | `patient`, розділ **Patients** | тварина, прив'язана рівно до одного власника |
| Медична картка | хронологія `GET /patients/{patientId}/visits` | усі прийоми пацієнта з діагнозами, призначеннями й медикаментами |
| Архівна картка | статус пацієнта `ARCHIVED` | неактивна картка, доступна лише для перегляду |
| Прийом | `visit`, розділ **Visits** | зафіксований медичний огляд пацієнта лікарем |
| Запис на прийом | `appointment`, розділ **Appointments** | резервація слота для лікаря й пацієнта |
| — статус «Заплановано» / «Завершено» / «Скасовано» | `SCHEDULED` / `COMPLETED` / `CANCELLED` | |
| Слот розкладу | `slot` у сітці **Schedule** | 30 хвилин розкладу лікаря |
| — вільний / зайнятий | `FREE` / `BOOKED` | |
| Конфлікт розкладу | помилка `409 SLOT_TAKEN` | спроба записати лікаря на зайнятий слот |
| Каталог медикаментів | розділ **Medications** | перелік препаратів, дозволених у клініці |
| Медикамент | `medication` | позиція каталогу з назвою та залишком |
| Залишок препарату | поле `quantity` медикамента, операція `adjust-stock` | поточна кількість одиниць препарату |
| Мінімальний пороговий залишок | поле `minThreshold` | нижче цього значення адміністратор отримує сповіщення |
| Сповіщення про низький залишок | `notification` типу `LOW_STOCK`, розділ **Notifications** | сигнал адміністратору після списання нижче порога |
| Адміністратор | роль `ADMIN` | керує обліковими записами, реєстрацією, розкладом і медикаментами |
| Лікар | роль `VETERINARIAN`; у шляхах і полях `doctor` (`/doctors`, `doctorId`) | веде прийоми та медичні картки |
| Вихідний день клініки | причина `NON_WORKING_DAY` | субота або неділя |
