# API-GATE: журнал перевірки перед проходженням етапу проєктування API

**Дата:** 2026-10-29
**Тип артефакту:** Журнал контрольної точки GATE (SDD Logging, SRS §6.4)
**Контекст:** Підсумкова перевірка артефактів проєктування REST API за SRS v1.0. Перевірку підготував ШІ-агент (Claude Code, Sonnet 5), рішення про GO закриває лише людина (R-13).
**Об'єкт перевірки:** `spec/api/openapi.yaml` (OpenAPI 3.0.3, 32 операції), `spec/addendum-001-api-decisions.md`, `spec/addendum-002-api-contract-decisions.md` (AD-01…AD-20, усі Approved), журнали `logs/`.

**Правило рішення.** Якщо хоча б одна з 10 умов не виконана, рішення REVISE; після виправлень гейт проводиться повторно.

---

## 1. Методи перевірки

- Автоматично: Redocly CLI (`lint`), Spectral (`spectral:oas`), власний скрипт перевірки за специфікацією після `redocly bundle --dereferenced` (простежуваність, URI, методи, схеми, коди, модель помилок, приклади), пошук внутрішніх термінів реалізації в тексті специфікації, запуск Prism.
- Вручну: звірка термінів із глосарієм SRS §3, огляд описів операцій, скріни інструментів (Swagger Editor, Redocly, Prism, Postman).

## 5. Відомі залишкові обмеження (не блокують GO)

- Позитивні приклади лише для 16 з 32 операцій (за рішенням людини).
- Відповідність mock контракту перевірено вибірково (скріни B–I і повторний прогін), без повного автоматичного контрактного тестування.
- Статус 405 для `DELETE` описано текстом, а не окремою відповіддю (операція `DELETE` не визначена за AD-09).
- Скрін зі Swagger Editor знято з версії до додавання прикладів; скрін D (`POST /appointments`) має інший `patientId`, ніж у фінальній специфікації. Людина вирішила залишити їх як є.
- У `info` відсутні `license` і `contact` (потрібні значення від людини).
- Матрицю простежуваності оновлено 2026-10-29 (пункт 16): колонка «Документація» заповнена для 41 вимоги (`operationId` та рішення адендумів); артефакти ще не закомічено (пункт 17).
