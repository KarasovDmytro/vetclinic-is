## 2. Рішення, прийняті людиною

| Рішення | Обґрунтування |
|---|---|
| Одна тварина — один власник (1:1), без винятків | Спрощення моделі для v1; притулок реєструється як звичайний власник |
| Платник завжди — зареєстрований власник | Страхові інтеграції — out of scope поточної версії |
| Конфлікт = лише один лікар на один слот | Прив'язка до кабінету/обладнання — out of scope |
| Облік медикаментів = лише списання + контроль мінімального залишку | Повноцінний склад, закупівлі, терміни придатності — out of scope |
| Картки ніколи не видаляються фізично; переводяться в статус *Архівна* | Збереження медичної історії як бізнес-вимога |
| Фіксовані слоти по 30 хвилин; один прийом = один слот | Найпростіша модель для v1 |
| Адміністратор не має доступу до медичних карток | Чітке розмежування відповідальності між ролями |
| Статуси запису: Заплановано / Завершено / Скасовано | Без проміжних статусів ("у процесі") |
| Статус *Завершено* — автоматично при збереженні прийому лікарем | Адміністратор не бере участі в закритті прийому |
| Статус *Скасовано* — виключно адміністратор | Лікар не може скасовувати записи |
| Ієрархії ролей вище адміністратора немає | Спрощення для v1; будь-який адміністратор створює акаунти обох ролей |
| Жорстке блокування при нестачі медикаменту | Мотивація персоналу підтримувати залишки актуальними |
| Лікар бачить картки всіх пацієнтів клініки | Складна прив'язка "лікар — свої пацієнти" не потрібна |
| Новий медикамент до каталогу додає лише адміністратор | Лікар лише обирає зі списку |

## 3. Припущення моделі, виправлені або відхилені людиною

| Припущення моделі | Статус | Прийняте рішення |
|---|---|---|
| Можливість існування буферного часу між прийомами | Відхилено | Буферний час не автоматизується |
| Можливість прив'язки прийомів до кабінетів чи обладнання | Відхилено | Out of scope |
| Ургентні випадки потребують системи автопріоритетів | Відхилено | Обробляються вручну адміністратором |
| Можливість довільної тривалості прийому | Відхилено | Виключно фіксований слот 30 хвилин |
| Наявність проміжного статусу "у процесі" для запису | Відхилено | Лише три статуси без проміжних |
| Можливість ролі "власник клініки" з розширеними правами | Відхилено | Плоска модель: лише Адміністратор та Лікар |
| М'яке попередження (з можливістю продовжити) при нестачі медикаменту | Відхилено | Жорстке блокування збереження |
| Функціонал вивантаження картки для стороннього ветеринара | Відхилено | Out of scope |
