# ADDENDUM-001: журнал затвердження рішень для проєктування API

**Дата:** 2026-10-28
**Тип артефакту:** Журнал рішень (SDD Logging, SRS §6.4)
**Контекст:** Початок проєктування REST API за SRS v1.0. ШІ-агент (Claude Code, Sonnet 5) за участі людини (KarasovDmytro) визначив вимоги, що потрапляють в API, і основні ресурси. Під час цього виявлено відкриті питання. Рішення оформлено в `spec/addendum-001-api-decisions.md` (тікет TSK-002).

---

## 1. Вхідні дані

- `spec/srs.md` v1.0 (REQ-F-001…048, REQ-NF-001…005, §9 критерії та BDD).
- Чотири логічні діри TSK-002 (журнал `plan-gate-decomposition-2026-10-03.md`, розділ 5), статус «відкрито».
- Відповідей на ці діри в наявних журналах і адендумах не знайдено (перевірено пошуком по репозиторію).

| AD-01 | Вхід за email і паролем, JWT 8 год, без refresh. Деактивований: 403 `ACCOUNT_DEACTIVATED`. Перший адміністратор через seed. Заборона деактивації останнього адміністратора (409) | TSK-002 п.1; REQ-F-001/002/003 |

| AD-03 | Скасований запис звільняє слот. *Завершено* і *Скасовано* кінцеві. Перенесення лише в межах того самого лікаря | TSK-002 п.3; REQ-F-023/024/025 |
| AD-04 | Запис архівного пацієнта заборонено. Архівування відхиляється при наявних записах *Заплановано*. Розархівування немає | TSK-002 п.4; REQ-F-015/021/035 |

| AD-06 | Лікар: лише читання власників, пацієнтів, каталогу. Довідник лікарів для обох ролей | SRS §4.1 проти REQ-F-030/044 |
| AD-07 | Прийом зберігає лише призначений лікар. Перелік препаратів після збереження незмінний | REQ-F-027/032/033/035/045 |

## 4. Відхилені припущення та зауваження

- Припущення агента, що відповіді на діри TSK-002 вже зафіксовані в адендумах, виявилося хибним: адендумів у репозиторії немає. Виправлено оформленням Addendum 001.
- Обсяг TSK-002 розширено з чотирьох до дев'яти питань (AD-05…AD-09 виявлено після створення тікета).
- Тлумачення «Повний CRUD» у SRS §4.1 як буквального відхилено на користь REQ-F-002/015/016/025 (AD-09).
